# 术语库 A/B 结果（2026-08-15）

问题：`src/data/lexicon.json` 到底改不改**英文选词**，还是只会给译文加梵文括注。

方法：15 段有鉴别力的样本，跨 5 部经论，译风固定为 `termRendering='translate'`
（意译优先、不附原语）。在这个模式下若术语库只会加括注，它就该毫无影响。
两臂唯一区别是 `context` 注不注入。脚本与选段规则见 `README.md`。

## 结果：15/15 全部有差异，零段逐字相同

每段约 20 处词级差异。**术语库确实大幅改变英文选词。**

### ⚠️ 这推翻了本仓库先前记录的结论

`docs/competitive-baseline.md` 曾据**单段** A/B 写下「术语库的实际作用是加梵文括注，
不是提高译词准确度」。**那个结论是错的**，错因正是 `README.md` 里写的那条：
随机单段没有鉴别力——恰好抽到了一段本来就没有分歧空间的文字。

同一个错误在这个项目里犯过两次（另一次是 gj.cool 头对头的前两版）。
**样本没有鉴别力时，"没有差异" 说明不了任何事。**

## 但方向是混合的，不能因此说"术语库有用"

| 变化 | 判断 |
|---|---|
| `惡魔` evil demons → **māras** | 更好，技术术语归位 |
| `法` states → **dharmas** | 更好，states 太含糊 |
| `涅槃` nirvana → **nirvāṇa** | 更好，转写规范 |
| `佛告` the Buddha → **the Blessed One** | **更差**，「佛」不是「世尊」 |
| `信` have faith → **believe** | 略差，般若语境下 faith 更准 |
| 若干 `(rūpa)`/`(vedanā)` 括注被删 | 中性（本就是不附原语模式） |

## 查出一个可定位、可修的缺陷类

术语库里有一批条目是**词元序列，不是可用的梵文**：

| | 条数 | 占比 |
|---|---|---|
| 总词条 | 8,610 | |
| 首选梵文是「多词」的 | 621 | 7.2% |
| 　其中**无任何变音符号**（高度疑似词元碎片） | **180** | 2.1% |
| 单词首选且带变音符号（健康的那批） | 6,130 | 71.2% |

碎片长这样——把它们当作「实证对照」喂给模型是有害的：

```
佛言    → bhagavant ah        何以故  → ka hetu
是名    → iti vac             所謂    → yad idam
從今日  → tena hi             不止    → na pratikram
```

**另有一类更隐蔽的错**：词元切分把带前缀的复合词拆坏了。

```
有漏 → āsrava(165) / sa āsrava(23) / bhava-āsrava(11) / sa(7)
```

`有漏` = **sāsrava**（有漏），不是 `āsrava`（漏）。切分器把 `sāsrava` 拆成
`sa` + `āsrava`，首选值丢了 `sa`，于是术语库**主动把模型往错处推**。
这类错不会被「必须有梵文原语」和「首选原语占比 ≥25%」这两道现有过滤拦住。

产物 `meta.sampledPrecision` 记的是抽 40 条、错 5 条（87.5%）。
上面这两类是那 12.5% 里**可被规则识别**的部分。

## 下一步该做什么

1. **过滤或降权无变音符号的多词首选值**（180 条，2.1%）
2. **修 `sa-` 类前缀的切分**（`有漏` 这种），或至少在首选值只差一个前缀时合并计数
3. 改完用**同一套 A/B 重跑**，看差异方向是否变好——这才是判断改动有没有用的方式

在 3 完成之前，**不要再断言术语库是竞争优势，也不要断言它没用**。
目前唯一站得住的说法是：**它影响很大，方向混合，且有已定位的缺陷。**

# 第二轮：修完匹配器之后的复测（2026-08-16）

## 做法

只重跑「注入」这一臂（`eval/rerun-with-arm.mjs`），拿 `lexicon-ab.json` 里存着的
上一轮结果作对照。不整轮重跑是因为「不注入」那一臂与术语库无关，
而上游是确定性解码——重跑只是白花别人的配额。

13/15 完成（2 段撞上上游 502）。context 变化 6 段，译文变化 7 段。

## 修好的两处，其中一处是意外收获

| 变化 | 说明 |
|---|---|
| `āsrava` → **`sāsrava`** | **这正是本文件原定的第 2 步**（`sa-` 前缀被切掉），被边界修复顺带修好了 |
| `asaṃjñin` → `asaṃjñi-samāpatti` | 無想定，更精确 |

## 但同时暴露出一个更要紧的问题：排序标准是错的

复测里出现了真损失——`檀波羅蜜` 掉出 context，译文里六波羅蜜的梵文括注
`(śīlapāramitā)`、`(kṣāntipāramitā)`、`(vīryapāramitā)` **全部消失**。

查下来**不是模型的问题，那几个词从来没进过 context**。一段《大智度論》命中 21 条，
上限 12 条，而排序是 `n` 降序——「越常见越优先」：

| 占了名额的 | 被挤出去的 |
|---|---|
| `是時`(1430)、`佛告`(330)、`一切世間`(920) | `尸羅波羅蜜`(99)、`羼提波羅蜜`(139)、`毘梨耶波羅蜜`(153)、`禪波羅蜜`(127) |

**常见恰恰意味着没有信息量。** 实测几种排法在这一段上的表现：

| 排序 | 六波羅蜜留住 | 虚词占位 |
|---|---|---|
| n 降序（原） | **2/6** | 3 |
| 词长优先 + 去叙事虚词 | **5/6** | 0 |

改为词长优先（n 作次序）+ 一份人工核对的叙事虚词表。
端到端复验：六个波羅蜜的梵文括注全部回到译文里。

⚠️ 只做到 5/6 而不是 6/6：差的 `禪波羅蜜` 被 `一切世間` 占了位，
而 `一切世間`（sarva-loka）是半实词，**没有把它塞进虚词表去凑那个数**——
为一段经文调虚词表就是过拟合。

## 两次被数据否掉的「合理」判据，记下来免得再试

| 判据 | 为什么否掉 |
|---|---|
| 按梵文对齐支持率 `sum(sa)/n` 过滤碎片 | `二無` 8.5%，而真术语 `阿賴耶識` 只有 10.5%、`涅槃` 19.8%——**任何能删碎片的阈值都会删真术语** |
| 「掐掉首字后若有更强词条则为碎片」 | 会把 **`比丘尼`**(1434)、`沙門尼`、`瞿曇彌`、`善女人` 全判成碎片，命中 28.4% 的词条 |

**共同教训：在这份数据上，看着有道理的统计判据会删真术语。**
所以现在的两处改动都不删数据——边界规则只改命中顺序，虚词表是人工小清单。

## 原定三步的现状

1. ~~过滤 180 条无变音符号的多词碎片~~ —— **未做**，但鉴于上面两次教训，
   动手前必须先量它会误伤什么
2. ~~修 `sa-` 前缀切分~~ —— **已被边界修复顺带解决**（`āsrava` → `sāsrava`）
3. 用 A/B 全量复测 —— **本轮做的就是这个**

「术语库是资产还是负债」仍未有定论：本轮修掉了两类错、暴露了一类新错并修掉，
但每次复测都还在发现新的失败模式。目前能说的是**方向在好转，且每一步都有实测支撑**。

# 盲评：这一轮改动到底有没有让译文变好

15 对「改前 vs 改后」译文在 `eval/blind-pairs.json` 里躺了很久没人判——
`blind-review.html` 要人逐条读英译，成本高到实际上不会发生。
所以改成两层：**能机器判定的部分零判断量出来，剩下的交给互不相通的盲评判官团。**

## 第一层：可机器判定的三条规则（`eval/auto-metrics.mjs`）

六条保真规则里，有三条说的是「不许出现某种形态」，不需要任何审美判断：

| 规则 | 改前 → 改后 |
|---|---|
| 规则 6　附注 / 文义解释 / 跨本比较 | 0 → 0 |
| 规则 6　括号里塞进整句 | 0 → 0 |
| 规则 3　计数式数目漏译（共 9 处） | 0 → 0 |
| 规则 2　固定语意象丢失（共 1 处） | 0 → 0 |

**结论：这三条规则在这批样本上一次都没派上用场。** 改前那一臂（完全没有保真规则）
本来就没犯过这几种错。它们是保险，不是改进——保留有意义（防的是罕见但严重的失败），
但**不能拿它们当「本轮提升了质量」的证据**。

⚠️ 这层数字是在探测器**通过变异测试之后**才可信的。第一版有三处缺陷，
全是喂已知坏值才发现的，读代码读不出来：

| 缺陷 | 后果 |
|---|---|
| `/\bi\.e\.\b/` 结尾的 `\b` 永远匹配不上（`.` 与空格都不是词字符） | 这条探测器是纯摆设，报的 0 毫无意义 |
| `十八` 被拆成 `十` + `八`，拿 ten / eight 去找 | 译成 eighteen 的**正确**翻译被记成两处漏译 |
| `三藐三菩提` / `三佛陀` 的音译用字被当成数目 | 般若系段落几乎每段都中，真实差异被假漏译淹没 |

修完之后「数目漏译」从虚高的 6→6 降到真实的 0→0。
**没做变异测试的话，这一轮会拿着一份全是噪声的报表下结论。**
探测器现在由 `tests/auto-metrics.test.mjs` 九条测试盯着，进了 `npm run verify`。

## 规则 5 的近似量：只能出候选，不能下判决

拿括注里的梵文词去 8,610 条术语库查出处：括注总数 119 → 112，查无出处 18 → 15。

**这个数不能当证据**。术语库只覆盖特定平行语料，查不到完全可能是正确却没被收录。
证据就在结果里：`śikṣāpada` 被标成「查无出处」，而它正是规则 5 里点名的**正确**形式。

但它指向了一处可以直接核的地方，而且核出来对本轮**不利**：

> 雜阿含「四不壞淨」段（#11），`聖戒` 改前译作 `śīla`，改后译作 `śikṣāpada`。
> 四不壞淨的第四支是 ariyakanta-sīla，`śikṣāpada` 是「學處」——**改后这一处更可能是错的**。
> 规则 5 拿「śikṣāpada 而非 śikṣā」举例，反而把模型往错的方向推了一把。

同段还能看到改后给 `四種`、`七寶`、`四天下` 这类**非术语**也加了梵文括注
（caturvidha / saptan-ratna / catur-dvīpa），属于括注泛滥。
两条都是单点观察，不足以定论，但都指向「规则 5 值得重新审」。

## 第二层：盲评判官团（`eval/judge-prep.mjs` → `eval/judge-score.mjs`）

我不能当判官——这批译文照我写的规则生成，我认得出自己的手笔。所以用 6 位
互不通气、也不知道两臂来历的独立判官，同一份卷子出两种 A/B 排布各 3 份。

**判分规则在看到任何一份答卷之前就写死了**，避免看着结果挑算法。三道闸门：

| 闸门 | 结果 |
|---|---|
| 4 道**已知答案**的对照题（砍掉三分之一段落 / 数目改错 / 去掉否定） | **24/24 = 100%** ✅ |
| 位置偏好（非平局判断里选 A 的比例） | 47%，无偏好 ✅ |
| 对调一致（同题两种排布指向同一臂才算数） | 11/15，翻脸 4 题记为噪声 |

对照题的破坏方式**故意不针对本轮任何一条规则**，否则就成了用自己的规则证明自己的规则。
评分脚本本身也做过变异测试：喂一个「永远选 A」的假判官，三道闸门全部报警
（对照 50%、选 A 100%、15 题全翻脸），确认闸门不是摆设。

### 比分：没有显著差异

**改后胜 2　改前胜 4　分不出 5　（p = 0.688）**

本轮改动**没有产生判官能稳定察觉的质量提升**。改前略占优但同样不显著。
这排除的是「有大幅提升」；小幅提升需要更大样本才量得出来。

### 比分不重要，败因分布才重要

判官写的败因里，有几处是**六位判官各自独立点名同一个缺陷**——那不是噪声：

| 题 | 缺陷 | 点名人数 | 落在 |
|---|---|---|---|
| 俱舍論 | `妙` 被括注成 **anuttara**，与同段 `無上` 撞车 | **6/6** | 改后 |
| 大智度論 | `有罪` 与 `無罪` 括注成同一个 **anavadya**，正反塌成一义 | **6/6** | 改后 |
| 大智度論 | 说话人 `佛` 被换成 "Blessed One" | **6/6** | 改前 |
| 俱舍論 | 漏掉 `異熟定`，`無永離染義` 译成 "no meaning" | **6/6** | 改后 |
| 雜阿含 | `分別` 译成 conceptual proliferation (prapañca) | 4/6 | 改前 |

两臂各有硬伤，但**性质不同**：改前输在普通译词选择，改后输在**括注注错**。

### 三类具体病因（已逐一查证到术语库）

**① 垃圾条目直接漏进译文——本轮改动引进的回归**

雜阿含那段的改后译文里出现 `He then joined his palms together and said (ah)`。
查术语库：`白佛言 = ah`，`ah` 是梵文动词词根 √ah（「说」），根本不能当括注。

链条是我们自己接上的：本轮把匹配改成**最长优先**，于是 `白佛言`（4 字）顶掉了
`佛言`（2 字）。而 `佛言 = bhagavant ah / ah / buddha bhagavant / vac` 首选是
`bhagavant`，`白佛言` 的**唯一**形式就是那个 `ah`。改前译文里没有这个括注。

同类残渣共 **169 条（约 2%）**：首选梵文形式是裸动词词根或代词——
`vac`(18) `ah`(12) `kṛ`(11) `dṛś`(9) `tad`(7) `bhū`(7) `śru`(7)……
⚠️ **别按长度一刀切**：那会连 `ṛṣi`(諸仙)、`eka`(獨一)、`aho`(嗚呼) 一起删掉，
正是本文件上面记过的那个坑。要删只能按「裸词根/代词」列人工清单。

**② 括注渗到反义词上**

术语库只有 `無罪 = anavadya`，段落里 `有罪` 与 `無罪` 并列出现，
模型把同一个 `anavadya` 挂到了两边——**一处教理对立被抹平**。
两臂 context 完全相同，所以这不是本轮引进的，是「提供括注」这件事本身的固有风险。

**③ 括注跑到邻近的词上**

术语库给的是 `無上 = anuttara`，模型把 `anuttara` 挂到了同段的 `妙` 上。
保真规则第 4 条写的正是「括注必须挂在它所解释的那个词上，不要挂到邻近的词」——
**带着这条规则的改后一臂照样犯，不带规则的改前一臂反而没犯。**
即：规则 4 没起作用，甚至可能因为把注意力引向括注而让括注更密。

### 这一轮真正学到的

1. **本轮改动在译文质量上是持平，不是提升**（p = 0.688）。此前所有「变好了」的说法
   都是我看着译文下的判断，没有量支撑，现在有量了，量说的是持平。
2. **术语库是资产还是负债，第一次有了硬证据：目前是负债多于资产**，
   而且负债的形态很具体——垃圾条目、反义渗透、邻词迁移，三类都能定位到条目。
3. **最长匹配优先这个改动有副作用**：它会让「更长但质量更差」的条目顶掉短而好的条目。
   排序只看长度不看质量，是这次回归的根。

### 下一步（尚未做）

按上面三条各有对策，但**每一条都必须先跑 A/B 再合并**——
这一整套评测存在的理由，就是防止再出现「看着变好了就合并」。
优先级：① 裸词根清单（证据最硬、改动最小）> ③ 排序加质量项 > ② 反义渗透（最难）。
