# 术语库 A/B 结果（2026-08-15）

问题：`src/data/lexicon.json` 到底改不改**英文选词**，还是只会给译文加梵文括注。

方法：15 段有鉴别力的样本，跨 5 部经论，译风固定为 `termRendering='translate'`
（意译优先、不附原语）。在这个模式下若术语库只会加括注，它就该毫无影响。
两臂唯一区别是 `context` 注不注入。脚本与选段规则见 `README.md`。

## 结果：15/15 全部有差异，零段逐字相同

每段约 20 处词级差异。**术语库确实大幅改变英文选词。**

### ⚠️ 这推翻了本仓库先前记录的结论

`docs/competitive-baseline.md` 曾据**单段** A/B 写下「术语库的实际作用是加梵文括注，
不是提高译词准确度」。**那个结论是错的**，错因正是 `README.md` 里写的那条：
随机单段没有鉴别力——恰好抽到了一段本来就没有分歧空间的文字。

同一个错误在这个项目里犯过两次（另一次是 gj.cool 头对头的前两版）。
**样本没有鉴别力时，"没有差异" 说明不了任何事。**

## 但方向是混合的，不能因此说"术语库有用"

| 变化 | 判断 |
|---|---|
| `惡魔` evil demons → **māras** | 更好，技术术语归位 |
| `法` states → **dharmas** | 更好，states 太含糊 |
| `涅槃` nirvana → **nirvāṇa** | 更好，转写规范 |
| `佛告` the Buddha → **the Blessed One** | **更差**，「佛」不是「世尊」 |
| `信` have faith → **believe** | 略差，般若语境下 faith 更准 |
| 若干 `(rūpa)`/`(vedanā)` 括注被删 | 中性（本就是不附原语模式） |

## 查出一个可定位、可修的缺陷类

术语库里有一批条目是**词元序列，不是可用的梵文**：

| | 条数 | 占比 |
|---|---|---|
| 总词条 | 8,610 | |
| 首选梵文是「多词」的 | 621 | 7.2% |
| 　其中**无任何变音符号**（高度疑似词元碎片） | **180** | 2.1% |
| 单词首选且带变音符号（健康的那批） | 6,130 | 71.2% |

碎片长这样——把它们当作「实证对照」喂给模型是有害的：

```
佛言    → bhagavant ah        何以故  → ka hetu
是名    → iti vac             所謂    → yad idam
從今日  → tena hi             不止    → na pratikram
```

**另有一类更隐蔽的错**：词元切分把带前缀的复合词拆坏了。

```
有漏 → āsrava(165) / sa āsrava(23) / bhava-āsrava(11) / sa(7)
```

`有漏` = **sāsrava**（有漏），不是 `āsrava`（漏）。切分器把 `sāsrava` 拆成
`sa` + `āsrava`，首选值丢了 `sa`，于是术语库**主动把模型往错处推**。
这类错不会被「必须有梵文原语」和「首选原语占比 ≥25%」这两道现有过滤拦住。

产物 `meta.sampledPrecision` 记的是抽 40 条、错 5 条（87.5%）。
上面这两类是那 12.5% 里**可被规则识别**的部分。

## 下一步该做什么

1. **过滤或降权无变音符号的多词首选值**（180 条，2.1%）
2. **修 `sa-` 类前缀的切分**（`有漏` 这种），或至少在首选值只差一个前缀时合并计数
3. 改完用**同一套 A/B 重跑**，看差异方向是否变好——这才是判断改动有没有用的方式

在 3 完成之前，**不要再断言术语库是竞争优势，也不要断言它没用**。
目前唯一站得住的说法是：**它影响很大，方向混合，且有已定位的缺陷。**

# 第二轮：修完匹配器之后的复测（2026-08-16）

## 做法

只重跑「注入」这一臂（`eval/rerun-with-arm.mjs`），拿 `lexicon-ab.json` 里存着的
上一轮结果作对照。不整轮重跑是因为「不注入」那一臂与术语库无关，
而上游是确定性解码——重跑只是白花别人的配额。

13/15 完成（2 段撞上上游 502）。context 变化 6 段，译文变化 7 段。

## 修好的两处，其中一处是意外收获

| 变化 | 说明 |
|---|---|
| `āsrava` → **`sāsrava`** | **这正是本文件原定的第 2 步**（`sa-` 前缀被切掉），被边界修复顺带修好了 |
| `asaṃjñin` → `asaṃjñi-samāpatti` | 無想定，更精确 |

## 但同时暴露出一个更要紧的问题：排序标准是错的

复测里出现了真损失——`檀波羅蜜` 掉出 context，译文里六波羅蜜的梵文括注
`(śīlapāramitā)`、`(kṣāntipāramitā)`、`(vīryapāramitā)` **全部消失**。

查下来**不是模型的问题，那几个词从来没进过 context**。一段《大智度論》命中 21 条，
上限 12 条，而排序是 `n` 降序——「越常见越优先」：

| 占了名额的 | 被挤出去的 |
|---|---|
| `是時`(1430)、`佛告`(330)、`一切世間`(920) | `尸羅波羅蜜`(99)、`羼提波羅蜜`(139)、`毘梨耶波羅蜜`(153)、`禪波羅蜜`(127) |

**常见恰恰意味着没有信息量。** 实测几种排法在这一段上的表现：

| 排序 | 六波羅蜜留住 | 虚词占位 |
|---|---|---|
| n 降序（原） | **2/6** | 3 |
| 词长优先 + 去叙事虚词 | **5/6** | 0 |

改为词长优先（n 作次序）+ 一份人工核对的叙事虚词表。
端到端复验：六个波羅蜜的梵文括注全部回到译文里。

⚠️ 只做到 5/6 而不是 6/6：差的 `禪波羅蜜` 被 `一切世間` 占了位，
而 `一切世間`（sarva-loka）是半实词，**没有把它塞进虚词表去凑那个数**——
为一段经文调虚词表就是过拟合。

## 两次被数据否掉的「合理」判据，记下来免得再试

| 判据 | 为什么否掉 |
|---|---|
| 按梵文对齐支持率 `sum(sa)/n` 过滤碎片 | `二無` 8.5%，而真术语 `阿賴耶識` 只有 10.5%、`涅槃` 19.8%——**任何能删碎片的阈值都会删真术语** |
| 「掐掉首字后若有更强词条则为碎片」 | 会把 **`比丘尼`**(1434)、`沙門尼`、`瞿曇彌`、`善女人` 全判成碎片，命中 28.4% 的词条 |

**共同教训：在这份数据上，看着有道理的统计判据会删真术语。**
所以现在的两处改动都不删数据——边界规则只改命中顺序，虚词表是人工小清单。

## 原定三步的现状

1. ~~过滤 180 条无变音符号的多词碎片~~ —— **未做**，但鉴于上面两次教训，
   动手前必须先量它会误伤什么
2. ~~修 `sa-` 前缀切分~~ —— **已被边界修复顺带解决**（`āsrava` → `sāsrava`）
3. 用 A/B 全量复测 —— **本轮做的就是这个**

「术语库是资产还是负债」仍未有定论：本轮修掉了两类错、暴露了一类新错并修掉，
但每次复测都还在发现新的失败模式。目前能说的是**方向在好转，且每一步都有实测支撑**。
